# レビュー手順（迷ったとき）

## 5 分で回すチェックリスト

1. [ ] PR / Issue に **課題 ID**（例: 1-3）が書いてあるか。無ければ研修生に確認  
2. [ ] [お客様からの改修要望.txt](../お客様からの改修要望.txt) の該当行を開く  
3. [ ] [02_レビュー判定基準.md](./02_レビュー判定基準.md) の **Must / Must not** だけ読む  
4. [ ] 動作確認手順が PR にあれば、その 3 パターン（正常・異常・境界）だけ試す or 信頼する  
5. [ ] 実装が参考コードと違う → [03_別解・許容一覧.md](./03_別解・許容一覧.md) を検索  
6. [ ] 判定を付ける: **LGTM / Comment / 要確認 / 要修正**（OK/NG だけにしない）

## 判定の優先順位

```
Must not 違反 → 要修正
Must 未達     → 要修正
Should 未達   → Comment（LGTM 可）
May の差      → Comment または無言 LGTM
```

## すぐ NG にすべきパターン（例外なく厳しめ）

- セキュリティ: 平文パスワード、SQL 連結、XSS 可能な `utext` の残置  
- 1-3: 500 のまま / catch のみ  
- 6-2: 0 件で全件フォールバックなし  
- 5-4: Controller の if だけで「認証完了」

## すぐ NG にしないパターン

- Repository と Controller のどちらでソートしたか（3-1）  
- datalist と jQuery UI（6-4）  
- `Pageable` と手書き LIMIT（6-5）  
- リダイレクト先やクラス名の違いだけ（Must が満たされていれば可）

## 5 分以上迷ったら

1. **要修正にしない**  
2. 研修生に **観測結果だけ** 質問する（実装方式は問わない）  

> 登録成功後、ブラウザのアドレスバーの URL を教えてください。F5 を 1 回押したとき、DB の件数は増えますか？

3. 回答後に Must だけ再判定  
4. 初めて見る別解なら `03` に 1 行追記してから LGTM  

## レビューで見る diff の目安

`AdministratorController`, `EmployeeController`, `templates/administrator/`, `templates/employee/`, `templates/error/`, 該当 Service・Repository, `WebSecurityConfig`

## Issue（質問）への返信の型

1. **結論**（1 行）  
2. **理由**（Must / 要望 txt ベース）  
3. **次のアクション**（確認すべき画面・ログ）  
4. 実装コードの丸投げは最後（ヒント程度）
