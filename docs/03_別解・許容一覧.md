# 別解・許容一覧（講師・メンター用）

研修生の **想定外実装** が来たとき、謝らずに判定できるよう整理した表です。  
最終判定は必ず [02_レビュー判定基準.md](./02_レビュー判定基準.md) の Must と照合してください。

**凡例**

| 判定 | 意味 |
|------|------|
| **OK** | LGTM または Comment で承認可 |
| **OK（△）** | Must は満たす。改善コメントを付ける |
| **NG** | 要修正 |
| **要確認** | お客様確認・仕様のすり合わせが必要 |
| **別タスク** | 今回の課題 ID の範囲外 |

## 新しい別解が来たとき（運用）

1. まず **Must を満たすか** だけ見る  
2. 満たすなら **この表に 1 行追加**（次回から迷わない）  
3. 満たさないが良い発想なら **Comment + 別タスク** を検討  
4. 判断に 5 分以上かかる → [04_レビュー手順.md](./04_レビュー手順.md) のエスカレ

## 返信テンプレ（コピペ用）

### 別解を認めるとき

> 実装方法はこちらの想定と異なりますが、要望の「〇〇」は満たせているため **この課題としては問題ありません（LGTM）**。  
> 参考までに、△の観点では 〇〇 も検討できます。

### 仕様確認を促すとき（3-1 など）

> 並び順は **お客様への確認プロセス** が評価対象です。Issue に「入社日降順にした理由」を 1〜2 行書いてもらえれば OK です。
