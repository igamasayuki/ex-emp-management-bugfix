# (3-1) 初級 従業員一覧の並び順 徹底解説

## 1. 研修生のスタート地点（バグの状態）
研修生は、一覧画面の表示がバラバラな現状を見て以下のように考えます。
> 「表示するたびに順番が違うな。とりあえず ID の小さい順に並んでいればいいのかな？ Controller の中で `Collections.sort()` とかを使って Java で並び替えればいいのかな？」

**ここで、ボス（指導者）は「効率的なデータの扱い方」と「UX（ユーザー体験）」を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「Java で並び替えるのも一つの手だけど、もし従業員が100万人いたらどうなる？ 全部取ってきてから Java で並び替えるのは効率が悪いよね。最初から DB に『この順番でちょうだい』と頼む方がスマートだと思わない？」
> 「あと、ただ ID 順にするのが一番使いやすいかな？ 従業員名簿を見る人は、誰を一番に探したいと思うだろう？」

研修生に、DB（SQL）での並び替え（ORDER BY）の効率性と、ユーザーにとって意味のある並び順（UX）を意識させます。

## 3. ロジックの組み立て方：SQLによるソート
「DBに命令する段階で順番を決めてしまおう。そして、実務を想定して『最近入社した人』がすぐわかるようにしよう」という方針を導きます。

1.  **SQLに並び替えを追加**: `ORDER BY` 句を使う。
2.  **項目を決める**: 今回は「入社日（hire_date）」を基準にする。
3.  **順序を決める**: 新しい順なので「降順（DESC）」にする。

## 4. メソッド・文法の駆使（実際のコード）

### Repositoryクラスの修正（EmployeeRepository.java）
```java
public List<Employee> findAll() {
    // SQLの末尾に ORDER BY を追加
    String sql = "SELECT ... FROM employees ORDER BY hire_date DESC";
    
    List<Employee> employeeList = template.query(sql, EMPLOYEE_ROW_MAPPER);
    return employeeList;
}
```

- **文法解説（ORDER BY）**:
    - `ORDER BY [カラム名] [ASC/DESC]`。
    - **ASC (Ascending)**: 昇順（小さい順、古い順）。
    - **DESC (Descending)**: 降順（大きい順、新しい順）。
    - 研修生には「最新の情報を上に持ってくるのは Web サービスの基本だよ」と教えます。

## 5. 研修生へのステップアップ課題
「もし入社日が全く同じ人がいたら、その人たちの間ではどういう順番になる？ 二番目の基準（例：名前順）を決めるには SQL をどう書けばいいかな？」

といった、複数条件によるソート（`ORDER BY hire_date DESC, name ASC`）への理解を深めさせます。

## 7. 💡 別解：Enum（列挙型）を活用したプロの設計
もし、入社日だけでなく「給料順」や「名前順」など、ユーザーが並び順を選べるようにしたい場合、文字列で SQL を組み立てるのは非常に危険（SQLインジェクションの標的）です。プロはここで **Enum** を使って安全に解きます。

### Enum によるソートキーの定義
```java
public enum EmployeeSortKey {
    HIRE_DATE_DESC("hire_date DESC"),
    SALARY_ASC("salary ASC"),
    NAME_ASC("name ASC");

    private final String sql;
    EmployeeSortKey(String sql) { this.sql = sql; }
    public String getSql() { return sql; }
}
```

### この設計が優れている理由：
1.  **型安全（Type Safety）**: Controller で受け取る型を `String` ではなく `EmployeeSortKey` にすることで、定義外の不正な文字列を Java レベルで完全にシャットアウトできます。
2.  **セキュリティ**: SQL の `ORDER BY` 句にユーザーの入力を直接連結せず、プログラム側で用意した安全な SQL 断片（`getSql()`）だけを使うため、SQLインジェクションを物理的に防げます。
3.  **意図の明確化**: 「何を基準に並べるか」という選択肢が一箇所にまとまっているため、仕様変更（例：新しいソート順の追加）が非常に簡単になります。
