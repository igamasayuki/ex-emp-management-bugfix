## 1. 研修生のスタート地点（バグの状態）
研修生は、既存のコードを見て以下のように考えます。
> 「何も入力せずに『登録』を押しても、そのまま処理が進んでしまうな。Controllerの中に `if (form.getName() == null)` みたいなチェックをたくさん書かなきゃいけないのかな？ 面倒だな……」

**ここで、ボス（指導者）は「もっと楽で、実務的な方法」を提示します。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「DBの定義が text 型で『制限なし』だからといって、システムとして何でも受け入れていいのかな？ もし名前が1万文字だったり、メールアドレスじゃない変な文字列が登録されたら、他の画面で表示する時にレイアウトが崩れたり、システムが止まったりしないかな？」

研修生に、プログラムの入り口で不正なデータを弾く「バリデーション（入力チェック）」の重要性を意識させます。

## 3. ロジックの組み立て方：宣言的バリデーション
「if文をたくさん書く代わりに、Javaには『この項目は必須だよ』『何文字以内だよ』というラベル（アノテーション）を貼るだけでチェックしてくれる仕組みがあるんだよ」と教えます。

1.  **Formクラスにラベルを貼る**: `@NotBlank`, `@Size`, `@Email` など。
2.  **Controllerで「チェック実行」を命じる**: 引数に `@Validated` を付ける。
3.  **結果を受け取る**: `BindingResult` でエラーの有無を確認する。

## 4. メソッド・文法の駆使（実際のコード）

### Formクラスの設計（InsertAdministratorForm.java）
```java
public class JuniorInsertAdministratorForm {
    @NotBlank(message = "氏名を入力してください")
    @Size(max = 50, message = "氏名は50文字以内で入力してください")
    private String name;
    // ...他のフィールドも同様...
}
```

- **文法解説（Jakarta Validation）**:
    - `@NotBlank`: 「空文字」や「スペースのみ」を弾きます。
    - `@Size(max = 50)`: 文字数制限をかけます。DBが text 型でも、アプリ側で境界値を決めるのがプロの仕事です。

### Controllerでの判定
```java
@PostMapping("/insert")
public String insert(@Validated InsertAdministratorForm form, BindingResult result) {
    
    // エラーがあるか確認
    if (result.hasErrors()) {
        // エラー時は、入力画面を表示（フォワード）して戻す
        return "administrator/insert"; 
    }
    // ...正常系処理...
}
```

- **文法解説（BindingResult）**:
    - `@Validated` で実行されたチェックの結果が入る「バインダー」です。
    - `result.hasErrors()` が `true` なら、どこかの項目で不合格があったことになります。

## 5. 重要なUXの視点：なぜ redirect しないのか？
研修生が「エラーの時も `return "redirect:/toInsert";` でいいですか？」と聞いてきたら、こう答えてください。
> 「もし君が長いフォームをやっとの思いで入力して、一箇所間違えただけで中身が全部消えて最初からやり直しになったらどう思う？ ……怒るよね（笑）。」

- **解説**:
    - `redirect:` を使うと新しいリクエストになり、Formの中身が空っぽになります。
    - `return "表示したいHTML";`（フォワード）を使うことで、SpringがFormの値を保持したまま画面を戻してくれるので、ユーザーは間違えた箇所だけを直せば済むようになります。

## 6. HTML側でのエラー表示
```html
<label th:errors="*{name}" class="error-messages">氏名エラー</label>
<input type="text" th:field="*{name}" th:errorclass="error-input" class="form-control" />
```

- **文法解説**:
    - `th:errors`: エラーがある時だけ、Formクラスで指定した `message` を表示します。
    - `th:field`: 入力された値を保持しつつ、エラーがあれば `th:errorclass` で指定したCSSクラス（赤枠など）を自動で付けてくれます。
    - これらのおかげで、HTML側も非常にスッキリ書けることを伝えます。

## 7. 付録：コード1行ずつ解説

### 7.1 Controller — バリデーションを「効かせる」

```java
public String insert(@Validated @ModelAttribute InsertAdministratorForm form, BindingResult result,
```

| 部分 | 意味 |
|------|------|
| `@Validated` | **これが無いと** Form の `@NotBlank` 等は実行されない |
| `BindingResult` | 直後の引数に置く（Spring の約束） |

```java
    if (result.hasErrors()) {
        return "administrator/insert";
    }
```

| 意味 |
|------|
| エラー時は **同じテンプレート** に戻す。`th:field` で入力が残る |

---

### 7.2 `InsertAdministratorForm`（抜粋）

```java
@NotBlank(message = "氏名を入力してください")
@Size(max = 50, message = "氏名は50文字以内で入力してください")
private String name;
```

| アノテーション | 意味 |
|----------------|------|
| `@NotBlank` | null・空文字・空白のみを拒否 |
| `@Size(max=50)` | 文字数上限 |
| `message` | エラー時に `th:errors` へ出る文言 |

---

### 7.3 `insert.html`

```html
<label th:errors="*{name}" class="error-messages"></label>
<input type="text" th:field="*{name}" th:errorclass="error-input" class="form-control"/>
```

| 属性 | 意味 |
|------|------|
| `th:errors="*{name}"` | `name` フィールドのエラーメッセージ一覧 |
| `th:field="*{name}"` | Form の `name` と双方向バインド |
| `th:errorclass="error-input"` | エラー時だけ CSS クラスを付与 |
