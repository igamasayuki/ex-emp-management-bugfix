# (5-3) 上級 パスワード暗号化 徹底解説

> **合格ライン**: 判定は [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(5-3)** / 別解は [03_別解・許容一覧.md](../03_別解・許容一覧.md) を参照。

## 1. 研修生のスタート地点（バグの状態）
研修生は、DBの中身を直接見て以下のように考えます。
> 「パスワードがそのまま『password123』って見えちゃってるな。もしこのDBの中身が外に漏れたら、全員のパスワードがバレちゃうじゃないか。……よし、これを『暗号化』して、見えないようにしよう！」

**ここで、ボス（指導者）は「暗号化」と「ハッシュ化」の決定的な違いを教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「『暗号』っていうのは、鍵があれば『元の姿に戻せる（復号）』ものだよね。でも、システムの管理者がユーザーのパスワードを元の姿に戻せる必要ってあるかな？ 管理者ですらパスワードを知ることができない、もっと安全な『一方通行』の方法があるんだけど、知ってるかな？」

研修生に、不可逆な変換である「ハッシュ化」の概念と、その重要性を意識させます。

## 3. ロジックの組み立て方：一方通行の変換
「パスワードは保存するのではなく、『正しいかどうか判定するための証跡』を保存するんだよ」と導きます。

1.  **ライブラリを導入する**: `spring-boot-starter-security` を使う。
2.  **登録時**: 生のパスワードをぐちゃぐちゃな文字列（ハッシュ値）に変換してDBに保存する。
3.  **ログイン時**: 入力された生のパスワードを、DBのぐちゃぐちゃな文字列と比較して判定する。

## 4. メソッド・文法の駆使（実際のコード）

### 設定クラス（WebSecurityConfig.java）
```java
@Bean
public PasswordEncoder passwordEncoder() {
    // 業界標準のハッシュアルゴリズム「BCrypt」を使う
    return new BCryptPasswordEncoder();
}
```

### 登録処理（FullAdministratorService.java）
```java
public void insert(Administrator administrator) {
    // 生のパスワードをハッシュ化して上書きする
    String encodedPassword = passwordEncoder.encode(administrator.getPassword());
    administrator.setPassword(encodedPassword);
    administratorRepository.insert(administrator);
}
```

- **文法解説（BCryptPasswordEncoder）**:
    - **`encode()`**: 生の文字列をハッシュ値に変換します。一度ハッシュにすると、二度と元の文字列には戻せません。
    - **ソルト（Salt）**: BCrypt は同じパスワードでも、実行するたびに違うハッシュ値を生成します。これにより、ハッシュ値のリスト（レインボーテーブル）を使った攻撃を防げることを伝えます。

### ログイン判定
```java
// × administrator.getPassword().equals(inputPassword) では判定できない
// ○ 専用の照合メソッドを使う
if (passwordEncoder.matches(inputPassword, administrator.getPassword())) {
    // 一致！
}
```

- **文法解説（matches）**:
    - ハッシュ値同士を `equals` で比べることはできません。
    - `matches(平文, ハッシュ値)` メソッドを使うことで、ソルトを含めた複雑な照合を安全に行ってくれます。

## 5. 研修生へのステップアップ課題
「もしユーザーがパスワードを忘れたらどうすればいい？ 管理者も元のパスワードを知らないんだから、教えてあげることはできないよね。」

と問いかけ、実務での「パスワード再発行（トークン発行）」という運用フローの必然性を理解させます。

## 6. まとめ：研修生に伝えたいメッセージ
> 「パスワードを平文で持つことは、お客様の信頼を人質に取っているのと同じだよ。万が一の時にも被害を最小限に抑える『ハッシュ化』は、エンジニアが守るべき最後の砦なんだ。」

## 変更箇所の差分（修正前 → 修正後）

### `AdministratorService.java` — 登録時

**修正前**

```java
public void insert(Administrator administrator) {
    administratorRepository.insert(administrator);  // 平文のまま DB へ
}
```

**修正後**

```java
@Autowired
private PasswordEncoder passwordEncoder;

public void insert(Administrator administrator) {
    String encodedPassword = passwordEncoder.encode(administrator.getPassword());
    administrator.setPassword(encodedPassword);
    administratorRepository.insert(administrator);
}
```

### `WebSecurityConfig.java` — エンコーダ Bean

**修正後**

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

> ログイン照合は Security が `UserDetails` のハッシュと入力パスワードを比較します。既存の平文データは **再登録** が必要です。
