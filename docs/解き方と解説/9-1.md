# (9-1) 初級 従業員削除 徹底解説

> **合格ライン**: [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(9-1)** / 講師確定: **DB 削除＋画像ファイル削除**  
> **講師用完成形**: `step5_beyond` / **研修生**: 本番パス `src/main/...`（`/employee/...`）

---

## 1. 研修生のスタート地点

削除機能はまだ無い。詳細画面には「更新」ボタンだけ。

> 「削除ボタンを `<a href>` で `/delete?id=1` にすればいいですよね？」

**指導者のストップ**: GET で削除は **危険**（ブックマーク・クローラで消える）。**POST + confirm** が Must。

---

## 2. 指導者からの問いかけ

> 「DB から行を消したあと、`static/img/山田.jpg` はサーバーに残り続ける。ディスクがゴミだらけにならないかな？」

→ 講師確定どおり **画像ファイルも物理削除**（Must）。

> 「削除したあと、同じ ID の詳細 URL を開いたらどう見えるべき？」

→ 一覧にいない。直打ちは 404 またはエラー画面（4-3 完成形があればそちらへ）。

---

## 3. ロジックの組み立て方

1. **detail.html** — 削除用 `<form method="post">` と `onsubmit="return confirm(...)"`
2. **Controller** — `@PostMapping("/delete")` で `id` を受け取る
3. **Service** — 削除前に `load` で画像ファイル名を取得
4. **Repository** — `DELETE FROM employees WHERE id=:id`
5. **ファイル** — `Files.deleteIfExists(画像パス)`
6. **完了** — `redirect:/employee/showList` ＋ 27-1 Flash

---

## 4. メソッド・文法の駆使（概要）

### HTML

```html
<form method="post" th:action="@{/employee/delete}"
      onsubmit="return confirm('本当に削除しますか？');">
    <input type="hidden" name="id" th:value="${employee.id}"/>
    <button type="submit" class="btn btn-danger">削除</button>
</form>
```

### Controller

```java
@PostMapping("/delete")
public String delete(String id, RedirectAttributes redirectAttributes) {
    employeeService.delete(Integer.parseInt(id));
    redirectAttributes.addFlashAttribute("successMessage", "employee.delete.success");
    return "redirect:/employee/showList";
}
```

### Service

```java
public void delete(Integer id) {
    Employee employee = employeeRepository.load(id);
    employeeRepository.deleteById(id);
    deleteImageIfPresent(employee.getImage());
}
```

## 5. よくある誤解

| 実装 | 判定 |
|------|------|
| GET `/delete?id=` | Must not |
| confirm なし | Must not |
| DB のみ削除、画像残置 | Must not |
| 論理削除（del_flg）のみ | 別解可だが原文は物理 DELETE |

## 7. 付録：コード1行ずつ解説

### 7.1 detail.html（削除フォーム）

```html
<form method="post" th:action="@{/beyondEmployee/delete}" ...>
```
| 属性 | 意味 |
|------|------|
| `method="post"` | 削除は **POST**（9-1 Must） |
| `th:action="@{/beyondEmployee/delete}"` | 送信先（研修生は `/employee/delete`） |

```html
onsubmit="return confirm('本当に削除しますか？');"
```
| 意味 |
|------|
| 送信直前に確認ダイアログ。キャンセルなら `false` で POST 中止 |

```html
<input type="hidden" name="id" th:value="${employee.id}"/>
```
| 意味 |
|------|
| どの従業員を消すか。画面に見えないが必須 |

---

### 7.2 Controller `delete`（BeyondEmployeeController 155〜165行）

```java
@PostMapping("/delete")
```
| 意味 |
|------|
| **POST のみ** 受け付けるマッピング |

```java
public String delete(String id, RedirectAttributes redirectAttributes) {
```
| 部分 | 意味 |
|------|------|
| `String id` | フォームの `name="id"` が入る |
| `RedirectAttributes` | 一覧へ Flash メッセージ（27-1） |

```java
employeeService.delete(Integer.parseInt(id));
```
| 意味 |
|------|
| Service に削除を委譲（DB＋画像） |

```java
redirectAttributes.addFlashAttribute("successMessage", "employee.delete.success");
return "redirect:/beyondEmployee/showList";
```
| 行 | 意味 |
|----|------|
| Flash | 一覧で一度だけ「削除しました」 |
| `redirect:` | PRG。削除の POST を F5 しても再実行しにくい |

---

### 7.3 Service `delete`（62〜77行）

```java
Employee employee = employeeRepository.load(id);
```
| 意味 |
|------|
| 削除**前**に画像ファイル名を取得（消した後は読めない） |

```java
employeeRepository.deleteById(id);
```
| 意味 |
|------|
| DB の行を物理削除 |

```java
deleteImageIfPresent(employee.getImage());
```
| 意味 |
|------|
| `static/img/` 配下のファイルを削除（講師確定 Must） |

```java
if (imageFileName == null || "no_image.png".equals(imageFileName)) {
    return;
}
```
| 意味 |
|------|
| デフォルト画像は消さない |

```java
Files.deleteIfExists(IMG_DIR.resolve(imageFileName));
```
| 意味 |
|------|
| ファイルが無くても例外にしない |

---

### 7.4 Repository

```java
String sql = "DELETE FROM employees WHERE id=:id";
template.update(sql, new MapSqlParameterSource().addValue("id", id));
```
| 行 | 意味 |
|----|------|
| `DELETE FROM` | 行の物理削除 |
| `WHERE id=:id` | 指定 ID のみ |
