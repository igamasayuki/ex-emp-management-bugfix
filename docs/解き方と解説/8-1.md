## 1. 研修生のスタート地点

本編 6-5 まで終えた時点では、詳細画面で **扶養人数だけ** 更新でき、成功後は **一覧** に `redirect` していることが多いです。

> 「名前や給料も直せるようにすればいいんだよね。登録画面と同じ入力欄を detail に足せばいいんじゃない？」

**指導者はここで止める。**

- 更新後は **当該従業員の詳細** へ（8-1 が本編の「一覧へ」を上書き）
- **Must で編集**: 名前・メール・電話・給料・扶養人数・**住所**
- **今回やらない**: 画像の差し替え、入社日（May）

---

## 2. 指導者からの問いかけ

> 「登録時（6-3）では `@NotBlank` や `@Email` を付けていたよね。更新だけルールが緩いと、空のメールで上書きできちゃう。どの Form を見本にする？」

→ `InsertEmployeeForm` のルールを **`UpdateEmployeeForm` に写す**（画像・入社日フィールドは除く）。

> 「更新ボタンを押したあと、F5 で二重更新されないようにするには？（1-1 の復習）」

→ 成功時は `redirect:/employee/showDetail?id=...` ＋ 27-1 の Flash（任意だが推奨）。

---

## 3. ロジックの組み立て方

| 項目 | 修正前（本編完了時） | 修正後（8-1） |
|------|----------------------|---------------|
| 画面で編集できる項目 | **扶養人数だけ** | **名前・メール・電話・給料・住所・扶養人数** |
| バリデーション | 扶養人数のみ | 6-3 登録時と同程度 |
| 更新成功後の行き先 | 多くは **一覧** | **その人の詳細** |
| 画像・入社日 | — | **表示のみ（編集しない）** |

実装の手順:

1. **Form 拡張** — 編集対象フィールドとバリデーション注解
2. **detail.html** — 表示専用の `<span>` を、Must 項目は `<input>` に変更
3. **showDetail** — 既存値を Form に詰める
4. **Repository.update** — `UPDATE` の SET 句を複数カラムに拡張
5. **Controller.update** — エラー時は詳細へフォワード、成功時は詳細へ PRG

## 4. メソッド・文法の駆使（概要）

### UpdateEmployeeForm（抜粋）

```java

@NotBlank(message = "メールアドレスを入力してください")
@Email(message = "メールアドレスの形式が不正です")
private String mailAddress;

@NotBlank(message = "電話番号を入力してください")
private String telephone;

@NotNull(message = "給料を入力してください")
private Integer salary;

@NotBlank(message = "住所を入力してください")
private String address;

@Pattern(regexp = "^[0-9]+$", message = "扶養人数は数値で入力してください")
private String dependentsCount;
```

### Controller — 成功時の遷移

```java
@PostMapping("/update")
public String update(@Validated UpdateEmployeeForm form, BindingResult result,
        RedirectAttributes redirectAttributes, Model model) {
    if (result.hasErrors()) {
        return showDetail(form.getId(), model);
    }
    Employee employee = new Employee();
    BeanUtils.copyProperties(form, employee);
    employee.setId(form.getIntId());
    employee.setDependentsCount(form.getIntDependentsCount());
    employeeService.update(employee);
    redirectAttributes.addFlashAttribute("successMessage", "従業員情報を更新しました");
    return "redirect:/employee/showDetail?id=" + form.getId();
}
```

### Repository — UPDATE の拡張

```java
String sql = "UPDATE employees SET name=:name, mail_address=:mailAddress, telephone=:telephone, "
        + "salary=:salary, address=:address, dependents_count=:dependentsCount WHERE id=:id";
```

## 7. 付録：コード1行ずつ解説（講師用）

完成形は `step5_beyond` のクラス名で記載しています。研修生は本番パスに読み替えてください。

### 7.0 処理の流れ（押したボタンから DB まで）

```text
① ブラウザ GET  /beyondEmployee/showDetail?id=12
   → Controller#showDetail … DBから Employee 取得
   → Form に今の値を入れる
   → detail.html を表示（入力欄に値が入った状態）

② ユーザーが名前などを直して「更新」ボタン
   → ブラウザ POST /beyondEmployee/update（フォームの中身が送られる）

③ Controller#update
   → @Validated で Form を検査（エラーなら ④へ戻す）
   → OK なら Employee にコピー → Service → Repository → UPDATE SQL
   → redirect で GET showDetail?id=12（PRG。F5 しても二重更新しない）
```

研修生は `/employee/...` に読み替えてください。
