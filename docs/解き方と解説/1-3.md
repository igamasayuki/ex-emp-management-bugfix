# (1-3) 中級 Eメール重複チェック 徹底解説

> **合格ライン**: 判定は [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(1-3)** / 別解は [03_別解・許容一覧.md](../03_別解・許容一覧.md) を参照。

## 1. 研修生のスタート地点（バグの状態）
研修生は、既存の「DBエラー（500エラー）」が起きる現象を見て以下のように考えます。
> 「メールアドレスが重複するとDBが怒ってエラーを出しているな。じゃあ、Controllerで `try-catch` を使って、DBエラーを捕まえればいいのかな？」

**ここで、ボス（指導者）は「プロの設計思想」を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「エラーが起きてから対処する（後手）のと、エラーが起きないように事前に確認する（先手）、どっちがスマートかな？ DBの制約に頼り切るのではなく、アプリケーションのロジックとして『重複は許さない』という意思表示をしよう。」

研修生に、例外処理で逃げるのではなく、プログラムとして正しく判定する「ビジネスロジック」の重要性を伝えます。

## 3. ロジックの組み立て方：Serviceによる事前チェック
「保存する前に、そのメールアドレスが既にDBにいないかServiceに聞きに行こう」という流れを作ります。

1.  **Serviceに検索メソッドを作る**: メールアドレスを引数に `Administrator` を探す。
2.  **Controllerで呼び出す**: 保存（insert）の直前で実行する。
3.  **結果で分岐する**: もし誰かが見つかったら（nullじゃなかったら）、エラーとして処理を中断する。

## 4. メソッド・文法の駆使（実際のコード）

### Serviceクラスの追加（AdministratorService.java）
```java
public Administrator findByMailAddress(String mailAddress) {
    // Repositoryを通じてDBに問い合わせる
    return administratorRepository.findByMailAddress(mailAddress);
}
```

### Controllerでの判定（MiddleAdministratorController.java）
```java
@PostMapping("/insert")
public String insert(@Validated InsertAdministratorForm form, BindingResult result) {
    
    // (1-3) 【先手】メールアドレスが重複していないかチェック
    if (administratorService.findByMailAddress(form.getMailAddress()) != null) {
        // 重複していたら、個別にエラーメッセージを追加する
        result.rejectValue("mailAddress", null, "そのメールアドレスはすでに登録されています");
    }

    if (result.hasErrors()) {
        return "administrator/insert";
    }
    // ...保存処理...
}
```

- **文法解説（rejectValue）**:
    - 通常のバリデーション（`@NotBlank`など）は単体で完結しますが、「DBにデータがあるか」といったチェックはアノテーションだけでは難しいです。
    - `result.rejectValue("フィールド名", エラーコード, "メッセージ")` を使うことで、後から手動でバリデーションエラーを追加できます。これにより、HTML側の `th:errors` で他のエラーと同じように表示されるようになります。

## 5. 研修生へのステップアップ課題
「もし、登録処理の直前で別の人が同じメールアドレスを登録しちゃったらどうなる？」と問いかけてみてください。
実務では「事前チェック」に加えて「DBのユニーク制約」や「トランザクションの分離レベル」といった話に繋がりますが、中級としてはまず**「アプリケーション層で正しくビジネスルールを実装する」**ことを合格基準とします。

## 6. まとめ：研修生に伝えたいメッセージ
> 「DBのエラー画面（500）をお客様に見せるのは、エンジニアの敗北だよ。丁寧な事前チェックと分かりやすいメッセージ（UX）で、ユーザーを導いてあげよう。」

## 変更箇所の差分（修正前 → 修正後）

### `AdministratorController.java` — 重複チェックの追加

**修正前**（重複時は DB 例外 → 500）

```java
@PostMapping("/insert")
public String insert(InsertAdministratorForm form) {
    administratorService.insert(administrator);
    return "employee/list";
}
```

**修正後**（`insert` 内に追記）

```java
if (administratorService.findByMailAddress(form.getMailAddress()) != null) {
    result.rejectValue("mailAddress", null, "そのメールアドレスはすでに登録されています");
}
if (result.hasErrors()) {
    return "administrator/insert";
}
```
