# (11-1) 初級 複数条件ソート 徹底解説

> **合格ライン**: [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(11-1)** / 講師確定: **29-1 検索結果でもソート・ページング（案 A）**  
> **講師用完成形**: `step5_beyond` / **研修生**: `/employee/showList`

---

## 1. 研修生のスタート地点

3-1 で入社日降順の固定 SQL、6-5 でページングはできている。

> 「Java で `list.sort()` すればソート完了ですよね？」

**指導者のストップ**: ページングがあると **今の10件だけ** 並べ替えることになる（Must not）。**DB で全件ソート → LIMIT/OFFSET**。

---

## 2. 指導者からの問いかけ

> 「`ORDER BY ${sort}` と URL の sort を直結したら、SQL インジェクションされない？」

→ **ホワイトリスト**（`hire_date`, `salary`, `name` のみ）。

> 「検索したあと、給料で並べ替えたい。検索条件は URL に残る？」

→ 案 A: `name` `mail` `telephone` `sort` `order` `page` を **すべて** リンクに載せる。

---

## 3. ロジックの組み立て方

処理順: **`WHERE`（29-1）→ `ORDER BY`（11-1）→ `LIMIT/OFFSET`（6-5）**

1. URL から `sort`, `order`, `page` を受け取る
2. `BeyondEmployeeSort`（if）または `BeyondEmployeeSortKey`（Enum）で安全な ORDER BY に変換
3. `findPage(...)` で 1 本の SQL
4. `list.html` のヘッダ・ページリンクにパラメータを引き継ぐ

---

## 4. メソッド・文法の駆使（概要）

### ホワイトリスト

```java
if ("salary".equals(sort)) {
    return "salary";
}
if ("name".equals(sort)) {
    return "name";
}
return "hire_date";
```

### Repository

## 6. 💡 別解：Enum（3-1 別解の発展）

3-1 の §7 で触れた `EmployeeSortKey` と同じ考え方で、**許可された ORDER BY だけ** を Enum に閉じ込めます。  
**11-1 でも Enum は使ってよい**（Must ではない）。講師用完成形 `step5_beyond` はこの別解を採用しています。

### Enum の定義（`BeyondEmployeeSortKey`）

```java
public enum BeyondEmployeeSortKey {
    HIRE_DATE_DESC("hire_date DESC", "hireDate", "desc"),
    HIRE_DATE_ASC("hire_date ASC", "hireDate", "asc"),
    SALARY_DESC("salary DESC", "salary", "desc"),
    SALARY_ASC("salary ASC", "salary", "asc"),
    NAME_DESC("name DESC", "name", "desc"),
    NAME_ASC("name ASC", "name", "asc");

    private final String sql;

    public String getSql() {
        return sql;
    }

    public static BeyondEmployeeSortKey fromUrl(String sort, String order) {
        // hireDate / salary / name と asc / desc の組み合わせだけ返す
        // 定義外 → HIRE_DATE_DESC
    }
}
```

| ポイント | 説明 |
|----------|------|
| `getSql()` | `ORDER BY` に連結する **完成した断片**（ユーザー入力を連結しない） |
| `fromUrl` | 画面の `sort=hireDate&order=desc` を Enum に変換 |
| if 別解との違い | 列と向きを **1定数にまとめる**（`NAME_ASC` など）。URL は従来どおり2パラメータのまま |

### Service / Repository（Enum 版）

```java
// Service
BeyondEmployeeSortKey sortKey = BeyondEmployeeSortKey.fromUrl(sort, order);
return employeeRepository.findPage(name, mail, telephone, sortKey, size, offset);

// Repository
sql.append(" ORDER BY ").append(sortKey.getSql());
```

### if 別解（`BeyondEmployeeSort`）との使い分け

| 方式 | クラス | 研修生の本番パス |
|------|--------|------------------|
| if ホワイトリスト | `BeyondEmployeeSort.toOrderColumn` / `toOrderDir` | `/employee/showList` にそのまま移植しやすい |
| Enum | `BeyondEmployeeSortKey.fromUrl` | 3-1 別解を伸ばしたい人向け。`step5_beyond` 完成形 |

`list.html` の `BeyondEmployeeSort.toggleOrder` は **どちらの方式でも共通** で使えます。

## 8. 付録：コード1行ずつ解説

### 8.1 BeyondEmployeeSortKey.java（Enum 別解・講師用完成形）

```java
HIRE_DATE_DESC("hire_date DESC", "hireDate", "desc"),
```
| 部分 | 意味 |
|------|------|
| 第1引数 | SQL にそのまま足す `hire_date DESC` |
| 第2・3引数 | URL の `sort` / `order` と対応づけるための内部値 |

```java
public static BeyondEmployeeSortKey fromUrl(String sort, String order) {
```
| 意味 |
|------|
| Controller から受け取った文字列を **定義済みの6通り** に限定 |

```java
return HIRE_DATE_DESC;
```
| 意味 |
|------|
| 不正な組み合わせは **入社日降順** にフォールバック（3-1 初期表示） |

---

### 8.2 BeyondEmployeeSort.java（if 別解）

```java
public static String toOrderColumn(String sort) {
    if (sort == null) {
        return "hire_date";
    }
```
| 意味 |
|------|
| 初回アクセス時は **入社日降順**（3-1 維持） |

```java
    if ("salary".equals(sort)) {
        return "salary";
    }
    if ("name".equals(sort)) {
        return "name";
    }
    return "hire_date";
```
| 意味 |
|------|
| URL の `sort` を **許可した列だけ** に変換。それ以外は `hire_date` |

```java
public static String toOrderDir(String order) {
    if ("asc".equalsIgnoreCase(order)) {
        return "asc";
    }
    return "desc";
}
```
| 意味 |
|------|
| `order` は **asc か desc だけ**。それ以外は desc |

---

### 8.3 Service `showList`（Enum 版）

```java
int offset = (page - 1) * size;
BeyondEmployeeSortKey sortKey = BeyondEmployeeSortKey.fromUrl(sort, order);
return employeeRepository.findPage(name, mail, telephone, sortKey, size, offset);
```
| 意味 |
|------|
| `offset` は 6-5 復習。`findPage` の Enum オーバーロードで `ORDER BY` + `LIMIT/OFFSET` を1本の SQL に |

---

### 8.4 Service `showList`（if 別解のイメージ）

```java
String column = BeyondEmployeeSort.toOrderColumn(sort);
String dir = BeyondEmployeeSort.toOrderDir(order);
return employeeRepository.findPage(name, mail, telephone, column, dir, size, offset);
```
| 意味 |
|------|
| 列名と向きを分けて渡す書き方。研修生の `/employee` 実装でよく使う |

---

### 8.5 Controller `showList`（88〜90行）

```java
if (sort == null) {
    sort = "hireDate";
}
if (order == null) {
    order = "desc";
}
```
| 意味 |
|------|
| 画面・リンク用の初期値。DB 列名とは別（`hireDate` → `hire_date` は Sort クラスで変換） |

---

### 8.6 list.html ソートリンク（74行付近）

```html
th:href="@{/beyondEmployee/showList(page=1, sort='name', order=${...}, name=${searchName}, ...)}"
```
| 部分 | 意味 |
|------|------|
| `page=1` | ソート変更時は **1ページ目から** |
| `sort='name'` | ソート列 |
| `order=${...}` | 同じ列なら asc⇔desc をトグル |
| `name=${searchName}` | **29-1 検索条件を維持**（案 A） |
