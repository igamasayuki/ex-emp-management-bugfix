# (4-3) 中級 パンくずリスト修正 徹底解説

> **合格ライン**: 判定は [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(4-3)** / 別解は [03_別解・許容一覧.md](../03_別解・許容一覧.md) を参照。

## 1. 研修生のスタート地点（バグの状態）
研修生は、詳細画面にある「従業員リスト」をクリックしても一覧画面に戻れない現象を見て以下のように考えます。
> 「リンクが `href="list.html"` のままになってるから、これを `href="/employee/showList"` に書き換えればいいんだな。……あれ？ ローカル環境だとうまくいくのに、サーバーにデプロイした時にリンクがズレることがあるのはなぜだろう？」

**ここで、ボス（指導者）は「コンテキストパス」と「URLの動的生成」を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「リンクを直接 `/employee/showList` って書くと、もしこのアプリが `http://mysite.com/app1/` みたいにサブディレクトリの中で動くことになったら、リンクが壊れちゃうよね。環境が変わっても、常に正しいURLを計算してくれる『フレームワークの力』を借りる方法を知ってるかな？」

研修生に、ハードコーディング（固定値の書き込み）の危険性と、URL生成をプログラムに任せる利便性を意識させます。

## 3. ロジックの組み立て方：ThymeleafによるURL解決
「HTMLのリンク（`href`）をそのまま使うのではなく、ThymeleafのURL専用の書き方（`@`記法）を使おう」と導きます。

1.  **HTMLの `href` を消す**: 静的なモック用のリンクは無視する。
2.  **`th:href` を使う**: Spring Boot（Thymeleaf）が実行時に正しいURLに変換してくれるようにする。

## 4. メソッド・文法の駆使（実際のコード）

### HTML側（detail.html）の修正
```html
<!-- 修正前 -->
<li><a href="list.html">従業員リスト</a></li>

<!-- 正解の修正 -->
<li><a th:href="@{/employee/showList}">従業員リスト</a></li>
```

- **文法解説（th:href="@{...}"）**:
    - ThymeleafでURLを扱うときは必ず `@` を使います。
    - 先頭に `/` をつけることで、アプリケーションのルート（一番上の階層）からのパスとして認識されます。
    - これにより、アプリケーションがどんな環境（URL）に置かれても、Spring Bootが自動的に最適な絶対パスへ変換してくれます。

## 5. 研修生へのステップアップ課題
「詳細画面へ飛ぶときのリンク `.../showDetail?id=1` のように、URLにパラメータを含めたいときはどう書けばいいかな？ 文字列結合を使わずに、Thymeleafらしく書く方法を調べてごらん。」

と問いかけ、`@{/path(id=${val})}` というクエリパラメータのスマートな書き方へと誘導します。

## 6. まとめ：研修生に伝えたいメッセージ
> 「Webの世界で『リンク切れ』は、ユーザーの信頼を失う一番の近道だよ。自分のPCだけで動けばいい、という考えを捨てて、環境の変化に強い『動的なパス生成』を常に心がけよう。」

## 変更箇所の差分（修正前 → 修正後）

### `employee/detail.html` — パンくず

**修正前**（リンクなし）

```html
<ol class="breadcrumb">
    <li>従業員リスト</li>
    <li class="active">従業員詳細</li>
</ol>
```

**修正後**

```html
<ol class="breadcrumb">
    <li><a th:href="@{/employee/showList}">従業員リスト</a></li>
    <li class="active">従業員詳細</li>
</ol>
```
