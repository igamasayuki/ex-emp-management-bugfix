## 1. 研修生のスタート地点

> 「デプロイ機能を Controller に実装するんですか？」

**指導者**: **いいえ。** 研修用サーバーに JAR を載せ、**手順書** に書く課題。

## 2. 指導者からの問いかけ

> 「ローカルで bootRun できたら、サーバーでもそのまま動く？」

→ DB ホスト・ポート・Java バージョンが違う。

> 「手順書に何を書けば半年後の自分が再現できる？」

→ 前提・ビルド・配置・起動・確認・トラブルシュート。

---

## 3. ロジックの組み立て方

1. 講師からサーバー情報をもらう（未確定なら着手待ち）
2. `./gradlew bootJar`
3. サーバーへ配置・`java -jar`
4. `docs/deploy/デプロイ手順書.md` に記録
5. **パスワードは Git に入れない**

---

## 4. メソッド・文法の駆使（概要）

手順書の章立て例は `docs/deploy/デプロイ手順書.md`（テンプレート）を参照。

```bash
./gradlew bootJar
java -jar build/libs/アプリ名.jar
```

## 5. よくある誤解

| 誤解 | 正しい理解 |

## 7. 付録：手順書の各行の意味（テンプレート）

### 7.1 ビルド章

```bash
./gradlew bootJar
```
| 意味 |
|------|
| Gradle で **実行可能 JAR** を `build/libs/` に生成 |

### 7.2 配置章

```bash
scp build/libs/xxx.jar user@server:/path/app/
```
| 部分 | 意味 |
|------|------|
| `scp` | ローカル → サーバーへコピー（講師指定の方式の一例） |
| `user@server` | 講師からもらう接続情報 |

### 7.3 起動章

```bash
java -jar -Dspring.profiles.active=prod /path/app/xxx.jar
```
| 部分 | 意味 |
|------|------|
| `-jar` | JAR を Java で実行 |
| `-Dspring.profiles.active=prod` | 本番用設定ファイルを使う（ある場合） |

### 7.4 確認章

- ブラウザでログインできる
- 従業員一覧が表示される
