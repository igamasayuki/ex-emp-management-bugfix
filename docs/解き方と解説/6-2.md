# (6-2) 中級 従業員曖昧検索 徹底解説

> **合格ライン**: 判定は [02_レビュー判定基準.md](../02_レビュー判定基準.md) の **(6-2)** / 別解は [03_別解・許容一覧.md](../03_別解・許容一覧.md) を参照。

## 1. 研修生のスタート地点（バグの状態）
研修生は、新しい「検索機能」を追加する際、以下のように考えます。
> 「SQL で `WHERE name = :name` と書けばいいのかな？ でもそれだと、フルネームを完璧に入れないとヒットしないから不便だよね。あと、もし検索結果が 0 件だったら、真っ白な画面になっちゃうけど、それでいいのかな？」

**ここで、ボス（指導者）は「曖昧さの許容」と「ユーザーを迷わせないUI」を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「名簿を探すとき、名字だけで検索したいことって多いよね。一部の文字だけでヒットさせるには、SQL をどう書けばいいかな？ あと、もし頑張って検索して『結果は 0 件です（以上）』って言われたら、ユーザーは次にどうすればいいか困っちゃわないかな？」

研修生に、SQL の `LIKE` 演算子による曖昧検索と、検索失敗時の「次の行動の提案（フォールバック）」の重要性を意識させます。

## 3. ロジックの組み立て方：気配りのある検索
「部分一致で柔軟に探しつつ、見つからなかった時は『ごめん、見つからなかったから一旦全員分出しておくね』という優しさをコードで表現しよう」と導きます。

1.  **Repositoryで部分一致**: `%キーワード%` を使った SQL を書く。
2.  **Serviceで判定**: 検索結果が空（empty）かどうかを確認する。
3.  **Controllerでリカバリ**: もし 0 件なら、警告メッセージを添えて「全件表示」に切り替える。

## 4. メソッド・文法の駆使（実際のコード）

### Repositoryクラスの修正（MiddleEmployeeRepository.java）
```java
public List<Employee> findByName(String name) {
    String sql = "SELECT ... WHERE name LIKE :name";
    // キーワードを % で囲むことで「一部でも含まれればOK」にする
    SqlParameterSource param = new MapSqlParameterSource().addValue("name", "%" + name + "%");
    return template.query(sql, param, EMPLOYEE_ROW_MAPPER);
}
```

- **文法解説（LIKE 演算子）**:
    - `%` は「任意の文字列」を意味するワイルドカードです。
    - 前後に `%` をつけることで、前方一致・後方一致・部分一致のすべてに対応できます。

### Controllerでの判定（MiddleEmployeeController.java）
```java
@GetMapping("/search")
public String search(String name, Model model) {
    // まずは検索を実行
    List<Employee> employeeList = employeeService.findByName(name);
    
    // (6-2) 【気配り】結果が 0 件だった場合の処理
    if (employeeList.isEmpty()) {
        model.addAttribute("message", "１件もありませんでした");
        // 0 件のまま終わらず、全件を再取得して表示してあげる！
        employeeList = employeeService.showList();
    }
    
    model.addAttribute("employeeList", employeeList);
    return "employee/list";
}
```

- **文法解説（isEmpty()）**:
    - List が空っぽかどうかをスマートに判定します。
    - 0 件のときに「全件表示」に差し替えることで、ユーザーは「あ、打ち間違えたかな。別の名前で探そう」とスムーズに次の操作に移れることを伝えます。

## 5. 研修生へのステップアップ課題
「今は名前だけだけど、もし『名前』または『住所』のどちらかに含まれていればヒットさせたい、となったら SQL はどう変わるかな？」

と問いかけ、`OR` 条件や、より複雑な検索要件への対応力を養わせます。

## 6. まとめ：研修生に伝えたいメッセージ
> 「検索機能は『見つけるための道具』だけど、本当の価値は『見つからなかった時』のフォローに現れるんだ。システムが一方的に拒否するのではなく、そっと全件データを見せてあげる。そんな『気の利くコード』が書けるエンジニアを目指そう。」
