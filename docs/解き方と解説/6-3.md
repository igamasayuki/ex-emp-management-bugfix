# (6-3) 上級 従業員登録 徹底解説

## 1. 研修生のスタート地点（バグの状態）
研修生は、この盛りだくさんの課題（画像・住所・採番）を見て、機能を作ることだけに必死になりがちです。
> 「とにかく動くコードを書こう！ 中級の Form クラスに新しい項目を足して、Controller も前のやつを改造すれば、早く終わるよね？」

**ここで、ボス（指導者）は「デグレード（退行）」の恐怖と「完全独立」の価値を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「中級のコードを改造して、もしバグを出しちゃったら、せっかく今まで動いていた中級の機能まで壊れちゃうよね。
> 実際の開発現場では、新しい機能を足すときに『古い機能を壊さない』ことが何より大切なんだ。
> 今回、あえて中級の部品を一切使わずに、上級専用の Form や Template をゼロから作ったのはなぜだと思う？」

## 3. ロジックの組み立て方：独立したサンドボックス
「過去の成果物を汚さず、新しい挑戦ができる『自分だけの実験場（パッケージ）』を作ろう」という、実務的なディレクトリ設計を導きます。

1.  **専用の器を作る**: `AdvanceInsertAdministratorForm` のように、名前からして独立したクラスを作る。
2.  **排他制御（synchronized）**: 見えない「同時実行」という敵からデータを守る。
3.  **外部知恵の統合**: AjaxZip3 のような既存技術を「目利き」して取り入れる。

### 上級専用 Form の定義
```java
// 中級の Form を継承（使い回し）せず、あえて新規作成する
public class AdvanceInsertAdministratorForm {

    // IDの最大値を取得して +1 する
}
```

## 5. 💡 ワンランク上のエンジニアリング・トーク
### 「なぜコードをコピペしてまで『分ける』必要があるのか？」
研修生は「同じようなコードなら、共通化した方がいいのでは？」と疑問に思うかもしれません。そこでこう伝えてください。

> 「共通化（DRY原則）は素晴らしい。でも、**『たまたま形が似ているだけの、別の役割を持つもの』を無理に共通化するのは、プロの設計では間違い**なんだ。
> 今回の『中級Form』と『上級Form』は、学習段階も目的も違う『別の生き物』。
> これを無理に一つにまとめると、将来中級の内容を少し変えただけで上級が動かなくなる『密結合の罠』にハマる。
> **『変更の影響範囲を限定する』ために、あえて分ける。** この勇気が、大規模開発を支える堅牢さ（ロバストネス）を生むんだよ。」

## 6. まとめ：研修生に伝えたいメッセージ
> 「上級編の壁は、機能の多さじゃない。機能が増えても『システム全体が美しく、整然としているか』を保つことなんだ。
> `synchronized` で見えないスレッドを守り、独立したパッケージで過去の資産を守る。
> この『守り』の意識があって初めて、プロの『攻め』の機能開発ができるんだよ。」
