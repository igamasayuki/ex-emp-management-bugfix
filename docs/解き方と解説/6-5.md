## 1. 研修生のスタート地点（バグの状態）
研修生は、大量のデータが表示される一覧画面を見て以下のように考えます。
> 「従業員が 100 人になっても、そのまま下にずらっと並べればいいよね。スクロールすれば見れるし。……え？ 実際の現場では一気に全部表示しちゃダメなの？」

**ここで、ボス（指導者）は「リソースの有限性」と「パフォーマンス」について教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「もし従業員が 1 万人、10 万人になったらどうなる？ 1 万人分のデータを一気に DB から持ってきて、一気に HTML に書き込んで、一気にブラウザで表示させようとしたら……。サーバーもブラウザも重くなって、最悪動かなくなっちゃうよね。必要な分だけを、小分けにして見せる方法を知ってるかな？」

研修生に、一度に全てのデータを扱おうとする「力技」の限界と、小分けにして読み込む「ページング」の必然性を意識させます。

## 3. ロジックの組み立て方：DBへの「小出し」依頼
「『全部くれ』ではなく、『○番目から○個だけくれ』という賢い頼み方をしよう。そして、今自分がどこにいるのかを計算する数式を組み立てよう」と導きます。

1.  **Repositoryで範囲指定**: SQL の `LIMIT`（件数）と `OFFSET`（開始位置）を使う。
2.  **全件数を把握する**: 総ページ数を計算するために、`SELECT COUNT(*)` が必要。
3.  **OFFSETを計算する**: 「(現在のページ番号 - 1) × 1ページあたりの件数」という公式を導き出す。

## 4. メソッド・文法の駆使（実際のコード）

### Repository での SQL（FullEmployeeRepository.java）
```java
public List<Employee> findAll(int limit, int offset) {
    // LIMIT で取得件数を、OFFSET で読み飛ばす件数を指定する
    String sql = "SELECT ... ORDER BY hire_date DESC LIMIT :limit OFFSET :offset";
    SqlParameterSource param = new MapSqlParameterSource()
            .addValue("limit", limit)
            .addValue("offset", offset);
    return template.query(sql, param, EMPLOYEE_ROW_MAPPER);
}
```

- **文法解説（LIMIT / OFFSET）**:
    - **LIMIT**: 「最大○件だけ取ってきて」
    - **OFFSET**: 「最初の○件は飛ばして、その次から取ってきて」
    - この 2 つを組み合わせることで、DB から必要な「1 ページ分」だけをピンポイントで取得できることを教えます。

### Service での計算（FullEmployeeService.java）
```java
public List<Employee> showList(int page, int size) {
    // OFFSET の計算ロジック
    // 1ページ目(page=1)なら、(1-1)*10 = 0件スキップ
    // 2ページ目(page=2)なら、(2-1)*10 = 10件スキップ
    int offset = (page - 1) * size;
    return employeeRepository.findAll(size, offset);
}
```

- **ロジック解説**:
    - なぜ `-1` をするのか、図を書いて説明すると納得感が高まります。

### HTML 側のページ番号表示（list_datalist.html）
```html
<th:block th:each="p : ${pageNumbers}">
    <li th:if="${p == currentPage}" class="active">
        <a th:href="@{/employee/showList(page=${p})}" th:text="${p}">1</a>
    </li>
    <li th:if="${p != currentPage}">
        <a th:href="@{/employee/showList(page=${p})}" th:text="${p}">1</a>
    </li>
</th:block>
```

- **文法解説（条件付きの class 付与）**:
    - `th:if` で現在ページだけ `class="active"` を付ける。三項演算子を使わず、条件分岐で読みやすく書く。

## 5. 研修生へのステップアップ課題
「今は 10 件ずつ固定だけど、ユーザーが『1 ページに 20 件表示したい』とか『50 件表示したい』と選べるようにするには、コードをどう直せばいいかな？」

と問いかけ、定数（PAGE_SIZE）をパラメータ化する設計の柔軟性について考えさせます。

## 7. 💡 別解：Enum（列挙型）を活用したプロの設計
「1ページに何件表示するか」を単なる数字（int）として扱うのは、実は少し危険です。悪意のあるユーザーが URL のパラメータを `size=1000000` と書き換えてリクエストを送ってきたら、サーバーのメモリがパンクしてしまいます。

### Enum による表示件数の制限
```java
public enum DisplaySize {
    COMPACT(10), COMFORT(20), DETAILED(50);

    private final int count;
    DisplaySize(int count) { this.count = count; }
    public int getCount() { return count; }
}
```

### この設計が優れている理由：
1.  **DoS攻撃対策**: サーバーが一度に処理できる「安全な件数」だけを Enum で定義しておくことで、想定外の大量データ読み込みによるサーバーダウンを防げます。
2.  **UIとの親和性**: 画面上の「表示件数切り替えプルダウン」の中身と、バックエンドのロジックをこの Enum 一つで完全に同期させることができます。
3.  **ビジネスルールの強制**: 「このシステムでは最大でも50件までしか一度に出さない」というルールを、プログラムの構造として強制できます。

## 9. 付録：コード1行ずつ解説

> §7 は「別解」節のため、付録は **§9** です。

### 9.1 Repository — LIMIT / OFFSET

```java
String sql = "SELECT ... FROM employees ORDER BY hire_date DESC LIMIT :limit OFFSET :offset";
```

| 部分 | 意味 |
|------|------|
| `LIMIT :limit` | 取得件数（例 10 件） |
| `OFFSET :offset` | 先頭から飛ばす件数。`(page-1)*limit` |

```java
public Integer count() { ... }
```

| 意味 |
|------|
| 全件数から総ページ数を計算するため |

---

### 9.2 Controller

```java
public String showList(Integer page, Model model) {
    if (page == null) {
        page = 1;
    }
    List<Employee> employeeList = employeeService.showList(page, 10);
```

| 行 | 意味 |
|----|------|
| `Integer page` | クエリ `?page=2` が入る。無ければ null |
| `if (page == null) { page = 1; }` | デフォルト 1 ページ目 |
| `showList(page, 10)` | 1ページ 10 件 |
