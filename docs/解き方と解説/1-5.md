# (1-5) 中級 確認用パスワード 徹底解説

## 1. 研修生のスタート地点（バグの状態）
研修生は、新しい入力項目を追加する際、以下のように考えます。
> 「確認用パスワード欄を作って、そこにも `@NotBlank` を付ければいいんだな。……でも、2つのパスワードが『同じかどうか』をチェックするラベル（アノテーション）なんてあるのかな？」

**ここで、ボス（指導者）は「相関バリデーション（複数の項目を組み合わせたチェック）」の考え方を教えます。**

## 2. 指導者からの「気づき」の問いかけ
研修生に以下のように問いかけてみてください。
> 「パスワードを2回入力させるのは、入力ミスを防ぐためだよね。もし1回目と2回目がバラバラのまま登録できちゃったら、ユーザーは後でログインできなくて困っちゃう。この『2つが一致しているか』という判定は、アノテーションだけで自動的にできるかな？ それとも、自分でロジックを書く必要があるかな？」

研修生に、単体項目のチェック（必須かどうか等）と、項目間の比較チェックの違いを意識させます。

## 3. ロジックの組み立て方：手動による相関チェック
「標準のアノテーションで足りない時は、Controllerの中で自分の手で判定して、エラーを追加してあげればいいんだよ」という流れを作ります。

1.  **Formに項目を増やす**: `password` に加えて `passwordConfirm` を追加。
2.  **Controllerで比較する**: `if (!form.getPassword().equals(form.getPasswordConfirm()))` で判定。
3.  **エラーを「後付け」する**: (1-3) でも使った `rejectValue` でエラーを登録する。

## 4. メソッド・文法の駆使（実際のコード）

### Formクラスの設計（MiddleInsertAdministratorForm.java）
```java
public class MiddleInsertAdministratorForm {
    @NotBlank(message = "パスワードを入力してください")
    private String password;

    @NotBlank(message = "確認用パスワードを入力してください")
    private String passwordConfirm;
    // ...
}
```

### Controllerでの判定（MiddleAdministratorController.java）
```java
@PostMapping("/insert")
public String insert(@Validated InsertAdministratorForm form, BindingResult result) {
    
    // (1-5) 【相関チェック】パスワードと確認用が一致しているか
    if (!form.getPassword().equals(form.getPasswordConfirm())) {
        // 不一致なら、手動でバリデーションエラーを追加
        result.rejectValue("password", null, "パスワードが一致しません");
    }

    if (result.hasErrors()) {
        return "administrator/insert";
    }
    // ...
}
```

- **文法解説（equalsメソッド）**:
    - 文字列の比較には `==` ではなく `.equals()` を使うという、Javaの基本を改めて思い出させます。
    - また、`passwordConfirm` が null の場合に備えて、`form.getPassword().equals(...)` のように、nullになりにくい方を左側に置く工夫も伝えるとプロっぽいです。

## 5. 研修生へのステップアップ課題
「今回はControllerで書いたけど、実は自作のアノテーションを作って、Formクラスだけでこのチェックを完結させる方法もあるんだよ。もっと大規模な開発になったら、どっちが管理しやすいと思う？」

といった、共通化・部品化への関心を引き出します。

## 6. まとめ：研修生に伝えたいメッセージ
> 「フレームワークが用意してくれた『ラベル（アノテーション）』は便利だけど、それが全てじゃない。複雑な業務ルール（仕様）を、自分のコードでどう表現するか。そこがプログラミングの本当の楽しさだよ。」
