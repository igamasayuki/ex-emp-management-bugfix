## 2. 課題別：確定仕様

### (8-1) 初級 従業員情報更新の拡張

#### お客様要望（要約）
扶養人数以外も更新可能に。バリデーション適用。更新後は **当該従業員の詳細** へ。

#### 講師確定仕様

| 項目 | 内容 |
|------|------|
| 編集可能項目（Must） | **名前、メールアドレス、電話番号、給料、扶養人数、住所** |
| 編集可能項目（Should） | 性別、入社日、郵便番号、特性 |
| 編集可能項目（今回対象外 / May） | **画像の差し替え**（Must にしない） |
| バリデーション | **6-3 `InsertEmployeeForm` と同等** のルールを `UpdateEmployeeForm` に適用 |
| エラー時 | フォワードで **詳細画面**、入力保持、`th:errors` |
| 成功時 | `redirect:/employee/showDetail?id={id}` ＋ 27-1 の Flash（任意だが推奨） |
| Repository | `UPDATE` で上記カラムを更新（扶養人数のみの SQL は拡張） |

#### 講師確定（2025-05）
- お客様原文の「名前、メール…等」に加え、**住所のみ** Must に格上げ。画像・入社日は対象外。

#### 正常系・異常系
- **正常**: 変更が DB に反映され、詳細に新しい値が表示される。
- **異常**: 未入力・形式不正 → 詳細にエラー表示、DB は更新されない。

### (11-1) 初級 複数条件ソート

#### 講師確定仕様

| 項目 | 内容 |
|------|------|
| 対象列（Must） | **入社日、給料、名前** |
| 操作 | 列ヘッダ（またはリンク）クリックでソート。再クリックで **昇順 ⇔ 降順** |
| 初期状態 | **入社日・降順**（3-1 維持） |
| ページング | **全件をソートしてから** LIMIT/OFFSET（6-5 と両立） |
| URL 例 | `/employee/showList?page=1&sort=hireDate&order=desc` |
| 検索モード | **29-1 検索結果でも 6-5 ページング＋本ソートを適用**（Must）。SQL は `WHERE` → `ORDER BY` → `LIMIT/OFFSET` |
| URL | 検索パラメータ（`name` `mail` `telephone` 等）と `sort` `order` `page` を **併記** |

#### 実装のヒント（講師用）
- `ORDER BY` の列名は **ホワイトリスト**（`hire_date`, `salary`, `name`）で SQL インジェクションを防ぐ。
- `order` は `asc` / `desc` のみ許可。
- **別解（Enum）**: `BeyondEmployeeSortKey`（`step5_beyond` 完成形）。if 版は `BeyondEmployeeSort`。どちらも可。

### (29-1) 初級 複数条件検索

#### 講師確定仕様

| 項目 | 内容 |
|------|------|
| 検索項目 | **名前、メールアドレス、電話番号**（各テキストボックス） |
| 条件 | 入力がある項目のみ **AND** で結合 |
| 一致方式 | **部分一致**（`LIKE %値%`） |
| 全項目空 | **全件表示**（6-2 同様） |
| 0 件 | メッセージ「**１件もありませんでした**」＋ **全件表示**（6-2 同様） |
| UI | 既存の検索フォームを拡張（名前だけの 1 欄から 3 欄へ） |

#### SQL イメージ
```sql
WHERE 1=1
  AND (:name IS NULL OR name LIKE :name)
  AND (:mail IS NULL OR mail_address LIKE :mail)
  AND (:telephone IS NULL OR telephone LIKE :tel)
```
（空欄はバインドを `null` にしてスキップする実装でも可）

### (33-1) 中級 デプロイ

#### 講師確定仕様

| 項目 | 内容 |
|------|------|
| 前提 | **講師がサーバー情報を共有してから** 研修生が実装・検証 |
| 成果物（Must） | `docs/deploy/デプロイ手順書.md`（環境・コマンド・注意点） |
| 成果物（Should） | 実行 JAR のビルド方法、`java -jar` 起動例 |
| 調査範囲 | 講師が **方式を指定**（例: `bootJar` を SCP して `java -jar`）。研修生は手順書に沿って実施 |
| 禁止 | パスワード・秘密鍵の Git コミット |

#### 33-1 で「決める」ことの意味（講師向け）
お客様要望は「**講師からサーバー情報をもらい、本番相当の環境にアプリを載せる**」ことです。コードの機能追加ではなく、**手順書＋実際の配置**が成果物です。「デプロイ方式」＝ JAR 直置きか Docker か等を、研修開始前に講師が一言指定すればよい（研修生に方式調査だけ任せる必要はない）。

#### 講師が共有すべき情報チェックリスト
- [ ] サーバー OS / SSH 可否
- [ ] Java バージョン（17 等）
- [ ] PostgreSQL の接続先（ホスト・DB 名・ユーザ）
- [ ] 配置パス・ポート（8080 等）
- [ ] ファイアウォール / リバースプロキシの有無
