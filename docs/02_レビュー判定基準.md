# レビュー判定基準（講師・メンター用）

研修生の PR / Issue / 質問を **OK/NG の二値ではなく**、契約（Must）に照らして判定するための基準書です。

- **詳細な実装手順・講師向け正解例**: [01_仕様検討_実装手順書.md](./01_仕様検討_実装手順書.md)
- **別解・よくある誤判定**: [03_別解・許容一覧.md](./03_別解・許容一覧.md)
- **迷ったときの手順**: [04_レビュー手順.md](./04_レビュー手順.md)
- **お客様要望（原文）**: [../お客様からの改修要望.txt](../お客様からの改修要望.txt)
- **追加課題（原文）**: [../追加課題.txt](../追加課題.txt)
- **追加課題・講師確定仕様**: [05_追加課題_講師確定仕様書.md](./05_追加課題_講師確定仕様書.md)（レビュー時はこちらを優先）

## 判定ラベル（PR / Issue で使う）

| ラベル | 意味 |
|--------|------|
| **LGTM** | Must をすべて満たす（Should は未達でも可） |
| **Comment** | Must は満たす。設計・保守性の提案のみ |
| **要確認** | 要望 txt とずれる可能性。研修生の「お客様確認」を評価 |
| **要修正** | Must 違反または Must not に該当 |
| **別タスク** | 動くが今回の課題 ID の範囲外（例: 6-6） |

**ルール**: **LGTM は Must クリア時のみ**。実装の書き方が講師のイメージと違っても、Must が満たされていれば LGTM。

## 改修対象（研修生が直接書き換える本番コード）

| 層 | 主なパス例 |
|----|------------|
| Controller | `AdministratorController`, `EmployeeController` |
| テンプレート | `templates/administrator/`, `templates/employee/` |
| エラー画面 | `templates/error/404.html`, `500.html` |
| Service / Repository | `AdministratorService`, `EmployeeRepository` 等 |
| 設定 | `WebSecurityConfig`（5-3, 5-4） |

## (1-1) 初級 画面遷移

| 区分 | 内容 |
|------|------|
| **Must** | 管理者登録 **成功後**、ブラウザは **GET** でログイン相当画面を表示する（PRG。アドレスバーが POST の URL のままにならない） |
| **Must** | 登録成功後、**従業員一覧に遷移しない** |
| **Must not** | 成功時に `return "employee/list"` や `return "administrator/login"` の **フォワードのみ**（リダイレクトなし） |
| **Should** | 登録完了メッセージが **1 回だけ** 見える（Flash 等） |
| **Should** | `administrator/login.html` に `infoMessage` 等の表示欄がある |
| **May** | リダイレクト先が `/`（ログイン画面）であれば可 |
| **確認方法** | 登録 → F5 で二重登録されないか。Network で 302 → GET か |

## (1-2) 初級 入力値エラー処理

| 区分 | 内容 |
|------|------|
| **Must** | バリデーションエラー時、**登録画面を再表示**する（リダイレクトしない） |
| **Must** | エラー時、**入力済みの値がフォームに残る** |
| **Must** | エラー内容が画面で分かる（`th:errors` 等） |
| **Must not** | エラー時に `redirect:` して入力値が消える |
| **Must not** | 未入力・明らかな不正値で DB に insert される |
| **Should** | Bean Validation（`@NotBlank`, `@Email`, `@Size` 等）を使用 |
| **Should** | 名前 max50 / メール max254 / パスワード 8〜16（講師と合意した境界） |
| **May** | Controller 内の if による手動チェック（動作すれば可。Should 未達としてコメント可） |
| **確認方法** | 空送信・7文字パスワード・不正メールで画面と DB を確認 |

## (1-3) 中級 Eメール重複チェック

| 区分 | 内容 |
|------|------|
| **Must** | 登録済みメールで登録しようとしたとき、**500 / Whitelabel を出さない** |
| **Must** | 登録画面に **分かるエラーメッセージ** を表示する |
| **Must** | 重複時は **DB に二重登録されない** |
| **Must not** | `try-catch` で例外を握りつぶすだけ（メッセージなし・500回避のみ） |
| **Should** | 文言「そのメールアドレスはすでに登録されています」（文言の微差は May） |
| **Should** | `BindingResult.rejectValue` でフィールドエラーとして表示 |
| **May** | DB の UNIQUE 制約を併用（アプリチェックに加えて推奨） |
| **確認方法** | 同一メールで 2 回目登録 → 画面・DB |

## (1-4) 初級 ダブルサブミット対策

| 区分 | 内容 |
|------|------|
| **Must** | 登録 **成功後**、ブラウザ更新（F5）で **再登録されない**（1-1 の PRG と一体） |
| **Should** | フォーム送信時にボタン非活性化等の **フロント対策** |
| **May** | トークン方式（SynchroToken）。今回の要望範囲外だが将来の別解として可 |
| **Must not** | PRG なしで「更新で再 POST できる」状態のまま |
| **確認方法** | 登録成功 → F5。フロントのみの場合はダブルクリックも目視 |

## (1-5) 中級 確認用パスワード

| 区分 | 内容 |
|------|------|
| **Must** | 確認用パスワード欄が存在する |

## (5-1) 中級 SQL Injection 対策

| 区分 | 内容 |
|------|------|
| **Must** | 報告された **SQL 連結箇所** が修正されている |
| **Must** | ユーザー入力が SQL 文字列に **直接連結されない**（プレースホルダ / PreparedStatement） |

| 区分 | 内容 |
